# Codex가 일반 ChatGPT를 하위 작업자로 쓰게 만들기 (MCP submit_result)

Codex 사용량을 아끼려고, 파일 없이 할 수 있는 고난도 추론(설계·검토·초안)은 일반 ChatGPT 대화에 넘기고 결과만 Codex가 받아 검수하는 구조를 설계한 메모다. 일반 Chat은 Codex의 하위 작업자로 직접 배정되지 않으므로, 결과를 되돌려 받는 통로를 MCP로 만든다.

## 무엇을 Chat에 넘기고 무엇을 Codex에 남기나
기준은 "저장소에 접근해야 하는가"다. 파일 없이 설명만으로 풀 수 있는 일은 Chat, 실제 코드와 대조·실행·반영이 필요한 일은 Codex가 맡는다.

| 일반 Chat | Codex |
|---|---|
| 아키텍처 대안 장단점 분석 | 실제 저장소 구조 확인 |
| 요구사항 모순·누락 찾기 | 현재 코드와 요구사항 대조 |
| 알고리즘·데이터 모델 설계안 생성 | 코드 작성과 통합 |
| 오류 설명 기반 원인 가설 | 로그 재현, 디버깅 |
| 테스트 관점·실패 사례 제안 | 테스트 작성·실행 |
| 설계 문서·릴리스 문안 초안 | 사실 확인과 최종 반영 |

## 절감률 계산식
`Codex 사용량 절감률 = 위임 가능 비율 × (1 − 전달·검수에 다시 쓰는 비율)`
- 코드 수정·테스트 중심: 30% × 0.8 = 24%
- 구현과 설계 반반: 50% × 0.85 = 42.5%
- 기획·아키텍처·문서 비중 큼: 70% × 0.9 = 63%

수치는 작성자의 가정이다. Codex가 Chat의 추론 단계마다 끼어들면 전달 비용이 늘어 절감률이 떨어진다. 짧게 문제와 완료 기준만 넘기고, 구조화된 결과를 한 번에 받는 것이 핵심이다.

## 협업이 성립하려면 필요한 5가지
Codex가 Chat에 메시지를 보내도, 대화 완료를 기다리거나 결과를 원래 작업으로 가져오지는 못한다. 그래서 아래를 하나의 추적 가능한 흐름으로 묶어야 한다.
1. 정확한 대상: 어느 계정의 어느 Chat 대화인지 확인
2. 맥락 유지: 작업 ID, 기준 코드 버전, 검수 기준을 함께 전달
3. 결과 회수: 사람이 복사·붙여넣기 하지 않아도 원래 작업이 찾을 수 있게
4. 알림: 요청을 보낸 바로 그 Codex 작업에 도착을 알림
5. 검수 기록: "도착"과 "채택"을 별도로 기록

## MCP로 만든 흐름
```
① Codex ──send_message_to_thread──▶ 지정된 ChatGPT 대화
② ChatGPT ──MCP submit_result──▶ 로컬 수신기 (작업 ID·권한 확인 → 파일 저장)
③ 알림 코드 ──codex queue──▶ 요청한 Codex 작업
④ Codex: 요청 일치·기준 버전·타당성 확인 → 채택 또는 거절
```
- ①은 기존 대화 전송 도구를 쓰며, 모델 API 호출이나 Codex 하위 작업자 생성이 아니다.
- ②는 Chat이 도구를 실제로 호출해야만 일어난다. 답변만 쓰고 끝내면 제출되지 않는다.
- ③의 알림은 "결과가 저장됐다"는 사실일 뿐, 채택 지시가 아니다.
- 현재 MCP는 결과 제출만 지원하고 저장소 쓰기는 막혀 있다. 범위를 제한한 읽기 전용 검색·발췌 도구가 생기면 위임 비율을 더 올릴 여지가 있다.

## 내 작업에 적용
- simAI처럼 AI API 설계를 맡은 프로젝트에서, 명세 누락 검토·데이터 모델 대안 비교는 Chat에 넘기고 구현·테스트만 Codex에 남기는 분업 기준으로 쓸 수 있다.
- 에이전트 위임을 설계할 때 "작업 ID + 기준 버전 + 완료 기준"을 넘기고 "도착/채택"을 분리 기록하는 패턴은 다른 멀티 에이전트 구조에도 그대로 적용된다.
