# The Moss Keeper: "HTML 코드만으로 만든 영상" 주장 검증 (Embedded MP4)

Fable 5.5로 프롬프트 한 번에 만들었다는 2D 영상 The Moss Keeper가 공유됐다. 영상·이미지 생성 모델 없이 HTML 코드만으로 만들었다는 설명이었는데, 페이지 소스를 열어 보니 실제 구조는 달랐다. 아래는 공유 글의 주장과 소스로 직접 확인한 내용을 나눠 적은 것이다.

## 공유 글의 주장
- Fable 5.5가 프롬프트 한 번으로 완성한 2D 영상이고, 이미지·영상 생성 모델은 쓰지 않았다고 한다.
- 이 결과를 보고 영상 생성 모델이 앞으로도 필요할지 의문이라는 감상이 붙어 있다.
- 페이지 메타 설명에는 "hand-drawn style anime scene"이라고 적혀 있어, 공유 글의 "애니메이션이 아닌 2D 영상"과 표현이 다르다.

## 소스로 확인한 구조
- HTML 한 파일이 약 31MB(디코딩 전 응답 기준 약 48MB)다. 대부분이 `<script type="text/plain" id="reel">` 안의 base64 문자열이다.
- 이 문자열은 `ftypisom`으로 시작하는 MP4이고, H.264(libx264)로 인코딩됐다. 길이 약 80.7초, 해상도 1920×1040이다.
- 페이지의 JS는 이 문자열을 `blob:` URL로 바꿔 `<video>`에 연결하는 플레이어(재생·시크·전체화면·소리 켜기)와, canvas로 그리는 필름 그레인 효과뿐이다.
- 즉 브라우저가 코드로 장면을 실시간 렌더링하는 방식이 아니라, 미리 렌더링된 영상 파일을 HTML에 내장한 것이다.

```js
// 개발자 도구 콘솔에서 영상이 내장물인지 확인
document.querySelector('video').currentSrc   // "blob:..." 이면 JS가 만든 Blob 영상
document.querySelector('video').duration     // 재생 길이(초)
```

## 해석할 때 주의할 점
- 코드로 장면을 그리고 그 결과를 영상으로 캡처·인코딩했을 가능성은 있다. 다만 이 페이지만으로는 제작 과정(코드 렌더링 여부, 프롬프트 횟수)을 확인할 수 없다. (보충)
- 따라서 "HTML 코드만으로 만들었다"는 것은 확인되지 않은 주장이고, "영상 생성 모델이 필요 없어졌다"는 결론도 이 사례만으로는 근거가 부족하다. (보충)
- 영상의 시각적 완성도는 이번에 평가하지 않았다.

## 내 작업에 적용
- 데모·시연 영상을 코드 기반으로 만든 뒤 mp4로 렌더링하는 흐름은 시도해 볼 만하지만, 공유된 사례의 제작 방식은 재현 가능한 형태로 공개되지 않았다. 도입 판단 전에 프롬프트·렌더링 스크립트가 공개되는지 먼저 본다.
- AI 결과물 소개 글은 "무엇으로 만들었다"는 설명과 실제 산출물 구조(소스, 파일 형식)가 일치하는지 직접 열어 확인하는 습관을 둔다.
