# ego lite로 채용 지원 한 사이클 자동화하기

> 2026-11-02 TIL

Claude Code + ego lite(ego-browser 스킬)로 **공고 수집 → 선별 → 기업·직무 분석 → 자소서 → 지원서 입력 → 노션 기록**까지 한 사이클을 돌려봤다. 최종 제출 버튼만 직접 누르고 나머지는 에이전트에게 맡겼다.

## 환경

| 구성 | 내용 |
| --- | --- |
| 에이전트 | Claude Code (Windows, 터미널) |
| 브라우저 | ego lite + `ego-browser` 스킬 (`/ego-browser`로 호출) |
| 작업 폴더 | `Career-Vault` (이력서·포트폴리오·기업분석·지원서 보관 폴더) |
| 프롬프트 | `Career-Vault/.ego-lite/ego-lite-job-search-prompts.md` |
| 외부 연동 | Open DART API (기업분석), Notion MCP (지원 현황 기록) |

Claude Code는 `Career-Vault` 최상위에서 실행한다. 프롬프트 안의 경로(`01_my_assets/`, `02_company_data/` 등)가 그 기준이다.

## 전체 흐름

| 단계 | 하는 일 | 도구 | 결과물 |
| --- | --- | --- | --- |
| 1 | 자소설닷컴 채용달력·수시 공고 수집 | ego-browser | `jobs.csv`, `jobs_excluded.csv` |
| 2 | 공고 원문을 읽고 내 배경과 대조해 적합도 평가 | ego-browser | `jobs_ranked.csv` |
| 2-1 | 추린 공고를 자소설닷컴 즐겨찾기에 등록 | ego-browser | 즐겨찾기 + csv 표시 |
| 3 | 지원 페이지의 입력 항목·문항·글자 수·전형 조사 | ego-browser | `02_company_data/apply_[기업].md` |
| 4 | 기업분석(사업보고서) + 직무분석(채용 사이트) | Open DART API + ego-browser | `02_company_data/..._기업분석.md`, `..._직무분석_[직무].md` |
| 5 | 경험 정리 + 분석 파일 기반 자소서 초안 | Claude Code | `..._자소서.md` |
| 6 | 지원서 입력, **제출 직전에서 멈춤** | ego-browser | 입력된 지원서 화면 |
| - | 화면 확인 후 **직접 제출** | 사람 | - |
| 7 | 노션 "기업별 합격 현황" DB에 행 추가 | Notion MCP | 노션 행 |

단계마다 "끝나면 멈추고, 다음 단계는 내가 말할 때만 진행해"를 넣어서, 사람이 중간에 확인하고 다음으로 넘긴다.

## 원칙

- **조회와 쓰기를 분리**: 1~4단계는 조회만. 내 계정에 기록이 남는 동작은 2-1단계(즐겨찾기)와 6단계(입력)에서만 허용.
- **되돌릴 수 없는 버튼은 사람이 누른다**: 최종 제출, 지원 완료는 에이전트가 누르지 않는다. 회원가입, 약관 동의, CAPTCHA, 서류 업로드가 나오면 제어권을 사람에게 넘긴다.
- **없는 내용은 만들지 않는다**: 공고·보고서·내 경험 파일에 있는 내용만 쓰고, 없으면 "확인 불가"로 남긴다. 추정치는 추정이라고 밝힌다.
- **애매하면 버리지 말고 보류**: 에이전트가 "원하는 직무와 거리가 멀다"고 임의로 빼지 않게, 포함/보류/제외로 판정하고 사유를 남긴다.
- **결과는 파일로 남긴다**: ego-browser는 실행 한 번이 끝나면 상태가 사라진다. 단계별 결과를 파일로 남겨야 새 세션에서도 이어갈 수 있다.

## 오늘 겪은 문제와 해결

### 1. 공고 수집이 불완전했다

- **증상**: 시험으로 5개를 모았는데, 목록 조회 방식이라 조회할 때마다 개수가 달라졌다(148건 → 범위를 넓히니 112건). 달력과 비교하니 12건 이상이 빠져 있었다.
- **원인**: 달력이 아닌 목록·키워드 필터로 수집했고, 직무명만 보고 걸렀다.
- **해결**: 1단계 프롬프트를 고쳤다.
  - 채용달력을 날짜별로 하루씩 읽고, 공고 안의 직무 목록과 상세 업무까지 확인
  - 날짜별로 "달력의 공고 수 / 확인한 수"를 보고하게 해서 누락을 바로 확인
  - 날짜 하나가 끝날 때마다 저장해서, 끊겨도 이어서 진행
  - 수시·상시 공고는 날짜별 수집이 끝난 뒤 따로 수집
  - 고용형태, 경력 요건, 판정, 사유 컬럼 추가

### 2. DART 접속이 막혔다

- **증상**: 기업분석 중 DART 연결이 끊기고 한동안 접속되지 않았다.
- **원인(추정)**: 에이전트가 짧은 시간에 보고서 페이지를 많이 열어서 일시적으로 접속이 제한된 것으로 보인다. DART는 짧은 시간에 요청이 과도하면 서비스를 제한할 수 있다.
- **해결**: 4단계를 **Open DART API** 방식으로 바꿨다.
  - 인증키는 환경변수 `DART_API_KEY`로 등록 (`setx` 후 터미널 재시작). 프롬프트·파일에 키를 적지 않는다.
  - 고유번호(corpCode) → 기업개황 → 정기공시 목록 → 주요 재무 → 원문 순서로 호출
  - 기업은 하나씩, 호출 간격 1초 이상. 한도 초과나 네트워크 오류가 나면 재시도하지 않고 멈춘다.
  - 비상장사처럼 사업보고서가 없으면 감사보고서로 대신하고 표시한다.
  - 대체 방법: 사업보고서 PDF를 직접 받아 폴더에 넣고 그 파일로 분석

### 3. 에이전트가 PDF를 못 읽었다

- **증상**: 공고 첨부(블라인드 채용 안내, 지원자격 상세, 직무기술서) PDF를 받았지만 "읽을 도구가 없다"며 넘어갔다.
- **원인**: 셸 명령으로 읽으려다 PDF 도구가 없다고 판단했다.
- **해결**: Claude Code의 **Read 도구로 PDF를 직접 열라**고 지시했다. 스캔 PDF도 페이지를 이미지로 볼 수 있다. 안 되면 `pypdf` 같은 추출 도구를 설치하게 한다.
- **배운 점**: 블라인드 채용 공고는 학교명, 출신지, 사진 같은 정보가 들어가면 감점이나 실격이 될 수 있다. 에이전트가 불분명한 항목을 비워두고 먼저 물어본 건 좋은 판단이었다.

### 4. 파일 위치 정리

- 지원 조사 파일(`apply_*.md`)이 폴더 최상위에 쌓여서, 기업분석 파일과 같은 `02_company_data/`에 저장하도록 프롬프트를 바꿨다.

### 5. 노션 행이 맨 아래에 추가됐다

- **증상**: Notion MCP로 행을 추가하니 표 맨 아래에 붙었다.
- **원인**: 노션은 API·MCP로 추가한 행을 항상 맨 아래에 붙이고, 특정 위치에 끼워 넣는 기능이 없다. 기존 표는 손으로 끌어서 최신순으로 맞춰 둔 상태였다.
- **해결**: 노션 뷰에서 정렬을 `회사` 내림차순으로 설정했다. 회사명이 `YYMMDD_`로 시작해서 최근 지원이 자동으로 맨 위에 온다.

## 단계별 핵심 프롬프트 패턴

```
/ego-browser .ego-lite/ego-lite-job-search-prompts.md를 읽고 N단계만 실행해줘.
끝나면 멈추고, 다음 단계는 내가 말할 때만 진행해.
```

- 처음에는 범위를 작게 ("공고 5개만 먼저") 잡고, 결과를 확인한 뒤 넓힌다.
- 프롬프트 파일을 고친 뒤에는 "파일을 다시 읽어줘. N단계를 수정했어."라고 알려준다.
- 대화가 길어져 에이전트가 헤매면 새 세션에서 이어하기 프롬프트로 결과 파일을 읽게 한다.

## 느낀 점

- 에이전트에게 맡길 일과 사람이 할 일을 **되돌릴 수 있는지**로 나누니 기준이 명확해졌다. 조회와 입력은 맡기고, 제출은 직접 한다.
- 처음 만든 프롬프트는 한 번에 완성되지 않았다. 시험 실행 → 에이전트 보고 확인 → 프롬프트 보완을 반복하면서 수집 방법, API 전환, 파일 위치가 정리됐다.
- 에이전트가 "무엇을 못 했는지, 어디가 불완전한지"를 스스로 보고하게 한 게 가장 도움이 됐다. 날짜별 개수 대조처럼 검증 방법을 프롬프트에 넣어두는 게 중요하다.
- 웹사이트를 화면으로 긁는 것보다 공식 API(Open DART, Notion MCP)가 있으면 그쪽이 훨씬 안정적이다.

- 노션 행 추가 후 서류 결과가 나오면 체크박스를 갱신하는 흐름
